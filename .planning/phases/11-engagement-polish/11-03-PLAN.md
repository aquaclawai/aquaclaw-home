  <action>
1. Install Lighthouse CLI as a dev dependency:
   ```bash
   npm install -D lighthouse
   ```

2. Start the production build and server to get accurate Lighthouse scores:
   ```bash
   npm run build && npx next start &
   ```
   Wait for the server to be ready on port 3000.

3. Run Lighthouse mobile audit on the homepage:
   ```bash
   npx lighthouse http://localhost:3000/en --output=json --output-path=./lighthouse-report.json --chrome-flags="--headless --no-sandbox" --form-factor=mobile --throttling-method=simulate
   ```

4. Parse the JSON report to identify which categories score below 90. Extract the specific failing audits from each category.

5. Apply targeted fixes based on common Lighthouse failure patterns. Below are the most likely issues and their fixes -- apply only what the audit flags:

   **Performance fixes:**
   - **Largest Contentful Paint (LCP):** If hero image or mascot is the LCP element, add `priority` prop to the `<Image>` component in HeroSection.tsx. Add `fetchPriority="high"` if not using next/image. Ensure hero image is above-the-fold and not lazy-loaded.
   - **Cumulative Layout Shift (CLS):** Ensure all images have explicit `width` and `height` props. Check that font loading in layout.tsx uses `display: swap` (already configured via next/font). Ensure StatsCounter and DiaryCarousel reserve space before hydration (use min-height on their containers).
   - **Total Blocking Time (TBT):** If `motion` animations cause long tasks, defer non-critical animations with `useReducedMotion` or lazy-load client components below the fold. Ensure DiaryCarousel, StatsCounter, and FeaturedContent use dynamic imports with `next/dynamic` if they are not already.
   - **Unused JavaScript:** Check if any large client-side bundles can be code-split. The Giscus component should already use `loading="lazy"` -- verify this.
   - **Image optimization:** Ensure all images use `next/image` with appropriate `sizes` prop for responsive serving. Pixel-art images should use `unoptimized={true}` per project convention.

   **Accessibility fixes:**
   - **Missing alt text:** Ensure all `<img>` and `<Image>` elements have descriptive `alt` attributes.
   - **Color contrast:** Check that text on colored backgrounds meets WCAG AA (4.5:1 for normal text, 3:1 for large text). The Bold & Playful design tokens should already pass -- fix any specific failures.
   - **Button/link names:** Ensure all interactive elements (buttons, links) have accessible names. Carousel prev/next buttons need `aria-label` props.
   - **Heading order:** Ensure headings follow sequential order (h1 -> h2 -> h3, no skipping).
   - **Touch targets:** Ensure all tappable elements are at least 48x48px on mobile.

   **SEO fixes:**
   - **Meta description:** Ensure the homepage has a `description` in its `generateMetadata`. If missing, add it to `src/app/[lang]/page.tsx`.
   - **Viewport meta:** Should already be set by Next.js -- verify.
   - **Structured data:** Not required for this phase, but ensure no broken structured data exists.

   **Best Practices fixes:**
   - **HTTPS:** Not applicable in dev, but ensure no mixed content references.
   - **Console errors:** Fix any runtime console errors visible during the audit.
   - **Deprecated APIs:** Address any flagged deprecated API usage.

6. After applying fixes, rebuild and re-run Lighthouse to confirm scores:
   ```bash
   npm run build && npx next start &
   npx lighthouse http://localhost:3000/en --output=json --output-path=./lighthouse-report-final.json --chrome-flags="--headless --no-sandbox" --form-factor=mobile --throttling-method=simulate
   ```

7. Clean up: Kill the next server process. Add `lighthouse-report*.json` to `.gitignore` if not already present. Do NOT commit the report files.

8. The `files_modified` list above covers the most likely files needing changes. Only modify files that the audit actually flags -- do not make speculative changes to files with no audit failures.

Note: Per user decision D-06, the target is >= 90 on mobile. If a specific category proves extremely difficult to reach 90 (e.g., Performance due to simulated throttling on a content-heavy page), document the score achieved and what would be needed to close the gap.
